## 1. PostgreSQL job search

- Preserve the endpoint and filters for keyword, category, location, rating, status, visibility, radius, and limit. Compare public, connection-only, owner, and assigned-member access.
- Add a Flyway migration with a weighted `simple` text vector, a GIN index, and trigram indexes for title and location. Reuse the existing `pg_trgm` extension.
- Filter eligible rows before limiting. Rank exact title or category matches, full-text matches, and then trigram matches. Use creation time and ID for stable ordering. Preserve chronological filter-only results.
- Add a provider setting that defaults to the current deployment behavior. Keep indexing OpenSearch during the observation release so that rollback requires only configuration.
- Add PostgreSQL integration tests and a repeatable comparison for 100 or more judged queries across English, Malayalam, transliteration, typos, nearby jobs, and misses. Compare top-five relevance by language, zero-result rate, p95 latency, CPU, and migration write impact.
- Move staging to PostgreSQL after all contract tests pass, no visibility leaks occur, top-five relevance is within 5% by language, and p95 latency is within 10% at comparable load.

## 2. Photo moderation

- Replace simulated scoring with recorded checks on quarantined bytes. Label historical simulated scores in admin. Preserve historical decisions and keep verification documents on the private verification path.
- Use ClamAV, bounded decoding, English and Malayalam Tesseract, and a local explicit-image classifier. Treat violence and other visual rules as separate categories. Normalize OCR before matching contact details. Ambiguous digits go to review.
- Claim queue jobs with a short PostgreSQL lease, scan outside transactions, and finalize only if the lease and scanned object version or checksum still match. Retry transient failures after 1, 5, and 30 minutes. Keep exhausted jobs private and route them for operational review.
- Approve only where all required checks completed and qualified. Reject confirmed malware, definitively invalid media, and qualified policy violations. Send uncertainty, incomplete coverage, and appeals to human review. Preserve visibility and contact-sharing rules.
- Return stable owner-only reason codes and short next-step messages. Show them on web, Android, and iPhone and deliver a single notification. Show check results and tool versions in admin. Provide an idempotent **Request review** action. Exclude raw OCR, detected contact details, and media bytes from logs and notifications.

## 3. Video moderation

- Reuse the photo queue, result contract, and decision policy. Scan the entire file. Use ffprobe and bounded FFmpeg decoding. Analyze scene changes and regularly spaced frames using OCR and visual checks. Transcribe audio with multilingual Whisper and detect spoken contact details.
- Record reliable evidence timestamps without exposing detected values. Distinguish silent uploads from decoding failures. Route unsupported or incomplete checks and ambiguous content to review.
- Calibrate on separate datasets before using held-out evaluation. Include legit repair work, appliance labels, English and Malayalam signage, code-switching, low light, brief overlays, silence, and broken uploads.
- Qualify each automatic rejection category only when the lower 95% precision bound reaches 99%. Qualify automatic approval separately for photos and videos when the upper 95% bound for serious missed violations is below 1%. Keep decisions in review mode when evidence is insufficient.
- Start with 10% of qualified uploads and audit automatic decisions for seven days before expanding. Use independent switches for approval and rejection by medium and reason.
- Verify leases, retries, object replacement, appeal deduplication, media permissions, notifications, and rollback. Run member and admin Playwright checks and native Android and iPhone checks.

## Visual detector qualification protocol

- Freeze the model revision, preprocessing, video sampling, and the image digest before recording scores. Track `photo` and `video` separately. Record the strongest eligible video frame score and the number of successfully checked frames. Treat an incomplete check as a review case.
- Use a calibration set to select possible thresholds. Assign consented, de-identified assets to calibration or holdout by original upload or recording session so variants and frames cannot cross the split. Include ordinary service work and boundary cases across the lighting, cropping, and content conditions in the delivery plan.
- Have two reviewers independently label whether explicit imagery is present before they see the detector result. Record disagreement and the adjudicated label. Keep original media in the authorized review environment and export only opaque identifiers, adjudicated policy labels, model evidence, and timings.
- Use an explicit-imagery evaluation label for the hypothesized rejection. The existing broad staff reason `policy_prohibited_content` also covers other cases, so it cannot serve as the ground-truth label by itself. Evaluate the rejection hypothesis separately for photos and videos. Run the held-out set only after locking the calibrated thresholds. At zero errors, each rejection gate needs at least 299 independently labeled automatic rejection candidates to meet the 99% one-sided precision requirement. Retain human review until each applicable policy category is independently qualified.
